DEBRIS RENDER OPTIMIZATION — v65
================================

Build ID: 20260803-65a6e9c4d2

PURPOSE

Keep dynamic brick debris visually rich on older or slower machines without
removing debris physics, collisions, fields, lifetime, or speed-based depth
ordering.

1. CACHED PATH2D OUTLINES

Before v65, every visible polygon shard sent all of its moveTo, lineTo and
quadraticCurveTo commands from Go/WASM to Canvas 2D on every rendered frame.
Complex stars and glass-like fragments could therefore cause many JavaScript
boundary calls per shard per frame.

v65 builds one Path2D outline when each shard is created. Rendering normally
requires only:

  choose cached opaque color
  set the shard transform
  fill the cached Path2D

Circles avoid per-frame trigonometry. Live debris-size changes rebuild the
cached paths once. If Path2D is unavailable, the renderer automatically uses
the compatible immediate-path fallback.

Compile-time switch:

  defaultDebrisUsePath2DCache = true

2. CACHED OPAQUE COLOR PALETTES

The 256-step pre-blended opacity palette is now attached to each shard as shared
cached render data. The hot loop no longer reconstructs a color-cache key and
looks up the palette from scratch for every shard on every frame.

The existing opaque rendering behavior remains unchanged: overlapping shards
occlude instead of accumulating transparency.

3. LOWER CANVAS STATE CHURN

The old per-shard sequence used save, translate, rotate and restore. v65 uses one
setTransform call per visible shard and one save/restore pair per debris layer.
Repeated adjacent fillStyle assignments are also skipped when the resolved color
has not changed.

4. ADAPTIVE OLD-SHARD DRAW DENSITY

All debris physics remains active. Only visual drawing is reduced when measured
render FPS falls well below the machine/display baseline.

The baseline is learned while there is no active debris, so a genuine 30 Hz
display is not automatically treated as a failing 60 Hz display.

Fresh shards and fast shards are always drawn. Only older, slower shards are
selected through a stable render ID, avoiding frame-to-frame flicker.

Defaults in config.go:

  defaultDebrisAdaptiveRendering       = true
  defaultDebrisAdaptiveTargetFPS       = 60.0
  defaultDebrisAdaptiveFreshSeconds    = 0.75
  defaultDebrisAdaptiveAlwaysDrawSpeed = 500.0
  defaultDebrisAdaptiveMaxStride       = 3

Possible adaptive states:

  1/1  draw every shard
  1/2  draw a stable half of older slow shards
  1/3  draw a stable third of older slow shards

Fresh and >=500 px/s shards remain visible in every state.

P OVERLAY

Press P to inspect:

  DEBRIS DRAWN       number drawn / number adaptively skipped
  DEBRIS RENDER      current old-slow-shard stride
  DEBRIS BASELINE    learned no-debris render FPS
  DEBRIS PATH CACHE  READY, ON, FALLBACK, or DISABLED

UNCHANGED

  debris count and generation
  240 Hz ball physics
  debris physics and collisions
  black-hole and magnet influence
  speed-dependent front/behind-brick depth ordering
  opacity, flash and fade behavior
  all attached v64 gameplay and tuning values
